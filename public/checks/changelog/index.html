Check catalog changelog

The machine-readable catalog is schemas/check-catalog.json (schema schemas/check-catalog.schema.json). catalog_version is the version of that file. It records the checks that already ship. It does not add any.

1.0.3

Adds behavior_no_input (0 points, low) on behavioural classification. A run over 3.5s with no pointer or key input observed is reported as no input, not as automated input; behavior_score_low is now only for input that was actually observed and scores under 0.25. A high severity finding caps the verdict at suspicious, whatever the score, and the verdict card names the top signal instead of saying nothing here reads as a bot when the report carries findings. The reason's since stays master until the next release.

1.0.2

Reads the same prototype-lie surfaces in a Service Worker as well as the page, a same-origin iframe, and a Web Worker. prototype_lie_mismatch still scores only when at least two contexts that produced a reading disagree. A missing or failed Service Worker registration is skipped, as is a plugins getter a worker does not expose. Points stay 15, medium. The reason's since stays master until the next release. Catalog 1.0.1, which shipped in v0.3.8, read the page, the iframe, and the Web Worker only.

1.0.1

Adds prototype_lie_mismatch (15 points, medium) on remote-control tells. The page, a same-origin iframe, and a Web Worker each read Function.prototype.toString and the navigator.webdriver, languages, and plugins getters. The reason scores only when those readings disagree. A patch that looks the same in every context keeps native_function_patched or prototype_getter_not_native and its existing points. The reason's since is master until the next release.

1.0.0

First published catalog of the checks and scored reasons shipped through v0.3.3. It lists every checks-table row, including rows that can be not available and rows that score nothing (TLS fingerprint, fingerprint surfaces), and every reason the Worker can subtract, including fingerprint_randomized at 0 points.

  • v0.2.0: the original server, browser, network and behaviour checks.
  • v0.3.0: the interaction test and its first 13 checks. v0.3.1 and v0.3.2 did not change scoring.
  • v0.3.3: server-derived behaviour evidence, focus and tab-visibility interaction checks, and fingerprint protection (a context mismatch, and randomization reported at 0 points).

What this file is for

The check guide explains each row. The catalog is the same list for a program: id, group, what is read, pass, warning, fail and not-available rules, points, the public page, and the version that added or last changed it. Those check pages are generated from this file, so the reads, rules, points, group, since and notes on them match the catalog.
