Fingerprint protection

Read the same fingerprint several times, in several places. Does it hold still?

What this check is

Privacy browsers change their fingerprint on purpose. Brave adds a little noise to canvas and audio readings for each site and session, Firefox can randomize or block them, and Safari adds noise in private windows. Anti-detection tools change the fingerprint too, but often only in the visible page. This check tells the two apart: it reads each fingerprint more than once, compares the page with a Web Worker and an iframe, and draws a control whose result is known in advance.

What Tells reads

  • Canvas: a small solid-colour square, read three times in the page, once in an iframe and once in a Web Worker. An unprotected browser returns exactly the colour that was drawn.
  • WebGL: the graphics vendor, renderer and limits, read the same way.
  • Audio: a short rendered sound, three times in the page and once in an iframe, plus a constant signal that should come back unchanged.
  • Fonts and voices: the installed fonts and speech voices, three times in the page and once in an iframe. A worker cannot read these.
  • Only counts and yes or no answers leave the page, never the values that were read.

How to read your result

  • Warning: A surface reads one value in the page and another in a worker or iframe. That is what changing only the visible page looks like. A real browser does not disagree with itself.
  • Pass: Every surface read steadily, or some were randomized or blocked. Randomized and blocked surfaces are named in the result but cost nothing, because privacy browsers and anti-detection browsers both randomize.

Why it matters

Randomizing a fingerprint is a privacy feature, and treating it as a bot signal would punish the people who choose privacy browsers. A change that covers only the main page is different, because the worker and the iframe still tell the truth. Telling the two apart keeps privacy-minded visitors in the clear while still catching patched pages.

In your report

Find it in the Checks performed list on the tool page. Each surface's class (stable, randomized_session, randomized_per_read, blocked or context_inconsistent) is in the report JSON under client.fingerprints.stability, any finding is under verdict.reasons, and the agent guide explains how to read them programmatically.
