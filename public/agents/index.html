Blowhorn Tells

For AI agents and scripts

Tells is built to be run by automation. This page is the standing orders: how to get a report, how to read it, and how not to misuse it. Everything here is also what the human page does; there is no separate agent back door.

Ways to get a report

1. Drive the page

Load tells.blowhorn.ai in the browser you are evaluating. The inspection runs on load. The run is finished when the raw report JSON appears in [data-tells-report="raw"] (pre#jsonOut, the Raw report panel). That text is the full /api/report response. The interaction report is at /client/interaction, with check statuses derived on the server. It is complete when /client/interaction/task/completed is true. Before Submit, that element holds No report yet. or a report whose interaction is not completed.

// Playwright / Puppeteer, same shape
await page.goto("https://tells.blowhorn.ai/");
await page.waitForFunction(() =>
  document.querySelector('[data-tells-report="raw"]')?.textContent.trim().startsWith("{"));
const report = JSON.parse(
  await page.$eval('[data-tells-report="raw"]', (el) => el.textContent));
// report.client.interaction is complete when report.client.interaction.task.completed is true

The verdict card (#verdictCard) shows the same verdict in words, with the score out of 100. The Copy JSON and Download JSON buttons hand over the identical object.

2. Call the API

RouteWhat it returns
GET /api/ping Server basics for your connection (IP view, headers, Cloudflare readings) plus the server time.
GET /api/check A verdict scored from the request alone: headers, IP reputation, TLS and managed bot signals. No browser readings involved. The body is { schema_version, ok, receivedAt, verdict, server } with schema_version 1 (schemas/check.schema.json).
POST /api/report The full report. Send the client readings object as JSON (192 KB at most); the response is { schema_version, ok, receivedAt, verdict, server, client, detections } (schema_version 1, schemas/report.schema.json), with the client object returned enriched with cross-context consistency readings. Download JSON and Copy JSON serialize that body. This route answers cross-origin callers with CORS headers, so a page or agent on another origin may post to it.

The surest way to learn the client payload is to run the page once and read the client object out of its report. The collectors that build it live in the open source for this site.

3. Run the CLI

The tells command prints that same JSON and a one-line verdict. Install it once from npm (package blowhorn-tells) or Homebrew, then run tells.

npm i -g blowhorn-tells
tells
tells --server-only

brew install blowhorn-ai/tap/tells
tells

Stdout is only the body. Stderr is <classification> score=<n>. Exit 0 is likely_human, --help or --version, 3 is suspicious, 4 is likely_bot, 2 means the run failed, and 1 is a usage error. A headless Playwright run is expected to exit 4. --server-only prints GET /api/check and needs no browser. Playwright is optional and no install adds it; after the npm install, npm i -g playwright && npx playwright install chromium enables the browser run. The command does not save the report. To run it once without installing, or from a checkout:

npx github:blowhorn-ai/tells
node bin/tells.js

4. Compare two saved reports

Download JSON on two runs, then open /compare/. Paste or drop both files. The page diffs the verdict label, score and reasons, each check row's status and summary, and the flag groups the result page already shows. It does not post the files and it does not keep them. If schema_version is missing or the two versions differ, scores are only comparable within one version; overlapping fields are still diffed. A file that is not a Tells report is rejected in plain words. Fields the capture redaction drops (IP addresses, WebRTC candidates, history length, extension probes, fingerprint hashes, GPU strings, font lists) are left out of the diff even when an older file still contains them.

How to read the verdict

  • verdict.score runs 0 to 100 and starts at 100. Every finding subtracts points.
  • verdict.classification is likely_human (75 and up), suspicious (45 to 74), or likely_bot (under 45). A high severity finding caps the classification at suspicious, whatever the score. verdict.risk is the same bands as low, medium, high.
  • verdict.reasons is the evidence: one entry per finding, each with an id, a severity of high, medium or low, a plain-words message, and the readings it came from.
  • Per-check results on the human page are derived from those reasons: a check with a high-severity reason reads Fail, with a medium or low reason reads Warning, with none reads Pass, and a check whose readings never arrived reads Not available. Not available is a statement about the browser or the plan this site runs on, not a failure.
  • detections lists which detection areas ran at all. A missing row means that area was not evaluated (for example the managed bot score on a plan without it), which is different from evaluating clean.

The methodology is the account of that score, the pass, warning, and fail verdict, and which version a number belongs to.

How to interpret a run

  • A bot verdict for an automated browser is the tool working. A stock Playwright, Puppeteer or headless Chrome run is supposed to score as a bot. Treat it as calibration, and measure your work by which reasons fire and how the score moves when your browser setup changes.
  • Compare like with like. Score a known-good, human-driven Chrome on the same machine and network as your reference, then diff the reasons, not just the score. IP reputation and latency findings follow the network, not the browser.
  • Consistency findings are the interesting ones. A spoofed value that agrees everywhere is a fingerprint choice; a value that disagrees between the request, the window, a worker and an iframe is a tell. The consistency sections exist to catch the second kind.
  • One run is one sample. Network intel, timing and behaviour readings vary between runs. Change one thing at a time and re-run.
  • The interaction test is optional and safe to take. It asks for one fixed phrase, tells check 42, so no real text is ever read. Its result only joins the report if a run completes it, and an agent that skips it loses nothing but that one check's evidence. Its 15 checks are provisional and warn-only until calibrated.

Rules of engagement

  • The API allows 30 requests per minute per route, method and source IP. Over the limit you get a 429 with retryAfterSeconds of 60. Back off; do not parallelize around it.
  • Never put real personal data in a report payload. The tool neither needs it nor keeps it: reports are scored and returned, not stored.
  • Findings describe this browser, this network and this moment. Do not present a report as a verdict about a person, a product or another website's defences.

The tool itself is at tells.blowhorn.ai. Every check it runs is explained in the check guide, and the platform guide maps the checks to the platforms where each one matters. The machine-readable catalog of those checks is schemas/check-catalog.json, catalog version 1.0.2. The changelog records that version.
